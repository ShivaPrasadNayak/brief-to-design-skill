# Meaning, concept and story

## 1. Investigating a name / brand / title
Do this when a name, brand, product or title is part of the brief and its meaning could shape the design.

1. **Split the name** into parts and languages (DaySutra = Day + Sutra; Kairos = Greek word; Nimbus = Latin).
2. **Look it up** — WebSearch/WebFetch for etymology, the company's own "about"/brand page, Wikipedia,
   Wiktionary, or a dictionary. Two agreeing sources before stating an origin as fact.
3. **Sort every finding into three bins** and keep them labelled in the brief and, where it shows, on the slide:
   - **Established** — sourced facts (official brand info, dictionary meaning). Cite.
   - **Convention** — common design associations (e.g. "blue commonly reads as trust in fintech").
   - **Interpretation** — our creative reading ("we treat 'sutra' as a thread that ties the day together").
   Never upgrade an interpretation to a fact. If nothing reliable is found, say "origin not verified" and design
   from the product's purpose and audience instead — don't invent a backstory.
4. **Mine associations**: literal meaning · origin · product purpose · audience · industry · values ·
   personality · emotions to evoke. Turn 2–3 of them into **visual metaphors** (thread → line motif; kairos =
   "the opportune moment" → a single highlighted point on a timeline; nimbus = cloud/halo → soft radial light).
5. **One metaphor wins.** Use it for the cover, a motif, and one signature slide/section. Don't stack three.

Real brands: use the official logo and colours (brand/press page); never redraw or "improve" a real logo.
New brand concepts: create a concept mark and label it "concept — not a registered asset".

## 2. Marketing thinking before layout
Settle these in a few lines (they drive palette, imagery, type and headlines):
- **Core message** — one sentence a listener could repeat.
- **Audience need** — the job, pain or ambition it speaks to.
- **Value proposition** — what's different, for whom, versus what alternative.
- **Strongest evidence** — numbers, demo, customer proof, research. No evidence → soften the claim.
- **Desired response** — approve, buy, try, remember, share, change behaviour.
- **Narrative angle** — pick from 3 concept angles, each implying a different visual language:

| Angle type | Example (AI platform) | Visual implication |
|---|---|---|
| Scale / ambition | "Intelligence at Scale" | wide imagery, big numbers, deep dark field |
| Transformation | "From Data to Decisions" | before→after, left-to-right flow, two-tone |
| Category creation | "The Next Operating Layer" | layered diagrams, architecture, stacked planes |
| Human / empathy | "Back to the work you love" | people photography, warm accent, quotes |
| Proof / outcome | "40% faster close" | data-led, charts as heroes, restrained colour |

A sustainability talk should not look like a cybersecurity talk: the angle decides the look.
No empty hype — "revolutionary", "game-changing", "seamless", "unlock" without evidence get cut.

## 3. Story structures (flexible — combine or drop sections; no filler)
**Short team update / idea pitch (5–8):** big idea → why now → problem/opportunity → key insight →
proposed approach → evidence → impact → ask/next steps.
**Leadership / executive (6–10):** the decision needed (slide 2, not slide 9) → recommendation → evidence
→ options considered → risks & mitigations → cost/impact → next steps & owners. Answer-first.
**Marketing / campaign (8–12):** audience truth → tension → proposition → campaign idea → how it shows up
(executions, mockups) → channels & moments → measurement → ask.
**Product launch (8–12):** problem → who feels it → product moment (show it) → how it works (3 steps) →
differentiation → proof → pricing/availability → CTA.
**Brand concept (8–12):** context & audience → name & meaning → positioning → identity (logo, colour, type)
→ identity in use (mockups) → architecture/touchpoints → launch ideas → next steps.
**Technical (6–12):** problem & constraints → architecture (diagram) → key decisions & trade-offs →
results/benchmarks → risks → roadmap. Clarity over flourish.
**Teaching / explainer:** hook question → mental model → worked example → common mistake → recap → practice.

**Documents (Word / PDF / notes):** executive summary first (the answer in 3–5 lines) → context → findings
(each heading a claim) → recommendation → appendix. Notes/one-pagers: title-as-claim, 3–5 sections, a table or
callout where it saves words.
**Web page / site:** hero = the thesis (what + for whom + proof or demo) → problem → how it works → proof
(logos, numbers, quotes — real or clearly marked placeholder) → detail/features → objection handling/FAQ → CTA.

## 4. Headline writing
- A headline states the takeaway: "Churn halves when onboarding < 3 days", not "Onboarding analysis".
- ≤ 10 words for slides; verbs and numbers beat adjectives.
- Skim test: the headlines alone, read in order, tell the story.
- Eyebrows name the section; headlines carry the point; body only what the headline can't.
- Claims need a basis on the slide (source line, "(model)", "(estimate)", "(Oct 2026)").
